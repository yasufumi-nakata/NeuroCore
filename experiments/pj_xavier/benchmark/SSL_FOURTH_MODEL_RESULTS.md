# 第4モデル：自己教師あり EEG 追加学習後の比較

## 結論

**EEG エンコーダーへ実データ 13.9833 時間を追加学習し，固定済み LLM へ接続する工程は成立しました．外部 ITU で旧 CBraMod 構成より高い AI 送信行動 AUROC を測定しましたが，脳波による自律操作の実証には達していません．**

ITU の fused 条件は，3分類 balanced accuracy（必ず1クラスを選択）38.10%，AI 送信対その他の AUROC 0.5997 でした．旧 CBraMod との差は +0.0838，観測参加者群を用いた対応付き 95%区間は [0.0056, 0.1514] です．一方，同じ記録内で EEG を入れ替えた条件や実波形を10秒前へずらした条件との差の区間は 0 を含みます．履歴だけで学習した比較モデルは AUROC 0.7239–0.8352 と引き続き上回りました．[外部24条件集計](itu_external_ssl_fourth_model_aggregate.json)

この実験は先行モデルの評価結果を確認した後に設計した**探索実験**です．新モデルの ITU 予測前に専用契約を固定し，ITU を追加学習・チェックポイント選択・しきい値調整へ使用していません．元3モデルと履歴モデルを再推論せず，保存済み19条件へ新5条件を追加しています．多重比較の補正や学習の反復を行っていないため，個別の95%区間だけを根拠に一般的な改善を確定しません．[専用契約](protocol.itu_ssl_external.v1.json)，[登録記録](ssl_external_registration.json)

## 何を学習し，何を固定したか

公式 CBraMod の約492万パラメーターを，マスクされた EEG の復元損失で追加学習しました．品質条件を満たした train 1,678窓 × 30秒 = 50,340秒，13.9833時間を使用しています．内訳は portable EEG 1,670窓，UniBa 8窓・240秒です．検証用522窓・4.35時間は選択用に分けています．同じ窓を複数 epoch 使用した時間を，異なる入力データの時間へ加算していません．[入力・学習プロトコル](../model/cbramod_ssl_training_protocol.json)

SSL の最良エンコーダーは検証損失で epoch 8／224 step を選択し，保存された最良チェックポイントと出力重みが一致することを照合しました．この追加学習の原波形 allowlist から ITU 26記録，元 UniBa validation/test 14記録を明示的に除外し，166配列と実際に使用した窓の所属を再検証しています．公式モデルの当初の事前学習データ全体について，重複がないと新たに証明したものではありません．[外部評価直前・直後の検証結果](itu_external_ssl_fourth_model_aggregate.json)

続いて，新エンコーダーと SmolLM2 1.7B を固定し，間の射影だけを UniBa train で学習しました．元 CBraMod 構成との比較では，データ，batch 32，最大30 epochs／900秒，学習率，seed，A/B/C の単一トークン出力，射影構造，LLM を揃えています．両方とも実際に30 epochsを完了しています．変更点は追加学習済み EEG エンコーダーの重みです．1回ずつの学習結果から，改善の再現性や最適な学習量までは判定できません．[固定した実験計画](../model/cbramod_ssl_plan.json)

### 実際に判断を採用するときの限界

AI 確率0.5を固定した二値判定では，AI 送信126例のうち38例を検出し，非送信504例のうち102例を誤検出しました．再現率30.16%，特異度79.76%，この抽出標本内の適合率27.14%です．

3クラスの最大確率0.8以上だけを採用すると，採用111／630例，採用例内正解46／111例 = 41.44%でした．棄却を誤りとして数えた BA は6.48%です．表の38.10%は，棄却しない強制選択時の BA なので区別が必要です．このスコアは実環境での操作許可を意味しません．連続 idle データや実タスクエピソードがないため，誤操作／分やタスク完了率は算出していません．[しきい値込みの全指標](itu_external_ssl_fourth_model_aggregate.json)

## 実行可能性と残るボトルネック

外部の5条件は Colab L4 で実測201.75秒で完了しました．CUDA 最大予約メモリは3,466,592,256 bytes，約3.23 GiB，CPU 最大 RSS は4,423,966,720 bytesです．設定した21 GiBのGPU予算内でした．fused の1例相当 p95 は48.47 msですが，これはCPU EEG encoder・転送・射影・LLM forwardの測定であり，配列の読込み，resampling，tokenization，ハーネス処理を含みません．**実機上で推論できたという資源確認と，オンラインシステム全体の応答時間の確認は別です．**[実測資源情報](itu_external_ssl_fourth_model_aggregate.json)

公開 EEG には非因果的な offline filter が含まれます．4.125秒の条件付き future support を想定して時刻を扱いましたが，公開元の実原信号からオンラインで同じ特徴が利用可能になることは未検証です．波形の公称振幅にも解消していない由来上の問題があり，品質条件を後から緩めたり，未知の倍率で補正したりしていません．多くの利用可能データを取得することと，目的に適した因果的な学習窓を増やすことは同じではありません．

次に必要なのは，時刻が保証された前処理，意思決定前の環境・コード状態，実行結果を記録した新しいエピソードです．公開 coding task の調査では課題文と初期 API は見つかりましたが，その時点のコード状態と完全な元テスト oracle は揃いませんでした．別に作成した Java ハーネスは合成 fixture の配線検証であり，EEG による作業完了の実績には含めていません．[ハーネスの資料監査と次の実装案](CODING_HARNESS_SOURCE_AUDIT.md)
