# Addendum: UniBa amplitude provenance and unit notation

**The V-versus-µV notation difference is consistent with the publisher's normal writer path. It is not, on its own, evidence that the EEG is mis-scaled.** This clarifies the interpretation of the literal `bids_header_unit_disagreement` flag retained in the earlier immutable [QC report](../ssl_corpus_preparation_20261122_v1/README.md). The raw files, sealed preprocessing protocol, earlier reports, models, cohorts, labels and thresholds remain unchanged.

## What the source code establishes

The publisher's `scripts/01-b_load.ipynb`, cell 15 (zero-based), assumes the input XDF EEG time-series values are microvolts and divides them by one million before constructing an MNE RawArray. It assigns the eight UniBa names CP3, C3, F5, PO3, PO4, F6, C4 and CP4. It adds `otree_phase` and `STI_artificial` as separate stim channels, applies the published 3–40 Hz and notch filtering, and requests BrainVision output from MNE-BIDS.

The declared requirement is MNE-BIDS 0.16.0. In that pinned version, `_channels_tsv` uses the RawArray's SI metadata when no original-file units are attached, producing V for voltage channels. Its `_write_raw_brainvision` independently selects µV for serialization. The declared pybv 0.7.6 then scales voltage data from V to µV and divides by the chosen 0.1 resolution when writing float32 samples. The header records µV and resolution 0.1 so that the inverse calibration restores nominal volts:

```text
stored_number = filtered_nominal_volts × 1,000,000 ÷ 0.1
decoded_volts = stored_number × 0.1 × 0.000001
```

This algebra and the exact pinned code explain the different unit labels without a second physical scaling error. The header itself says it was written using pybv 0.7.6. Requirements and that header comment are provenance evidence; they do not prove that every distributed binary was generated by precisely the published notebook and every listed dependency version.

The actual unresolved assumption lies **before** the exported BIDS data: whether the XDF stream really supplied the assumed microvolt values, unit metadata, channel ordering and hardware calibration. The publisher README and load notebook explicitly state that the original XDF recordings are not distributed. The available experiment-app LSL server emits behavioral markers, not the original EEG device stream, so it cannot close that gap.

## Channel and normalization checks

All 18 admitted UniBa training headers and channel tables were freshly checked. They declare eight EEG channels in the expected order and two TRIG channels, `otree_phase` and `STI_artificial`. The Xavier inputs select only the eight explicit EEG names; both extra channels are excluded. No declared AUX/stim mixture was found in these inputs. This does not verify the upstream device's physical wiring or that its XDF columns were correctly labeled before export.

The inspected exporter has the explicit microvolt-to-volt step and the normal native writer calibration. No demonstrated double-scaling or normalization reversal was found. Later notebook PSD baseline ratios and logarithms are feature computations; the inspected code does not feed their inverse or their normalized values back into the distributed EEG export. These are bounded static-code findings, not proof of the undocumented original execution.

## Existing training-window amplitude description

The audit opened only the 18 sealed array files belonging to the existing **400 training windows** (8 channels, 448 samples, 1.75 s, 256 Hz). All array SHA-256 values were reverified; 1,433,600 stored values were inspected. No validation/test array was opened, and action labels were not used to select or group the diagnostic. No model forward, fitting, threshold tuning or new sample selection occurred.

| Statistic across the 400 windows | Median | p95 | Maximum |
| --- | ---: | ---: | ---: |
| Largest absolute sample, nominal µV | 414.27 | 3,619.72 | 30,947.28 |
| Largest within-channel peak-to-peak, nominal µV | 721.00 | 5,564.52 | 58,528.74 |
| Largest channel std, nominal µV | 108.82 | 887.13 | 8,488.40 |
| Largest absolute channel mean, nominal µV | 2.69 | 37.74 | 343.96 |

Twenty-one of the 400 existing short windows have largest absolute amplitude <=100 µV. Three hundred seventy-five have every channel's std >=0.01 µV, and 15 meet both descriptive conditions. **These counts are not a new eligible cohort or a revised evaluation.** The original 1.75 s case/control windows and the SSL 30 s resampled windows differ in duration, selection and processing; their threshold percentages are not interchangeable.

The very large nominal amplitudes therefore are observable in both the full-record SSL diagnostic and existing short training inputs, while some short windows also contain nearly flat channels. The available evidence does not identify their cause. Artifacts, an upstream scale/calibration issue, missing original processing details and other explanations remain hypotheses. Neither the amplitude distribution nor the software conversion agreement establishes the physical validity of the signal or a causal explanation of any negative model result.

## Evidence and limits

The full 400-window distributions, per-channel and pseudonymous source distributions are in `train400_amplitude_summary.json`; per-window identifiers and values remain private. `header_channel_mapping_audit.json` records source/header/table hashes and the declared channel checks. `provenance.json` pins the publisher cells and primary writer source hashes, separates confirmed behavior from unknowns, and records the unchanged experiment boundary.

Primary source files examined:

- [AI-assisted coding release 20801101](https://zenodo.org/records/20801101), downloaded `scripts.tar.gz`, `resources.tar.gz`, README and requirements.
- [MNE-BIDS v0.16.0 write.py](https://raw.githubusercontent.com/mne-tools/mne-bids/v0.16.0/mne_bids/write.py), SHA-256 `c89f071ae9ec0561b28771e5bc60d94522f5a581b41950002936e0d1958578a2`.
- [pybv v0.7.6 io.py](https://raw.githubusercontent.com/bids-standard/pybv/v0.7.6/pybv/io.py), SHA-256 `ad2d7bbf9855fb424b0da3da3b4a5461ea7ec8f41aad488a7df142e44722c9f0`.

Resolving the remaining issue requires the original XDF/EEG bridge unit metadata and values, device calibration/version information, and export execution provenance. No scale correction is justified solely by the different V/µV notation, and no automatic correction was applied.
