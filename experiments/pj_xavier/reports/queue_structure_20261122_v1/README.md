# EEG 取得キュー全件の構造監査

**15.821 TB は，609 releases に含まれる全取得候補ファイルの公開サイズ合計です．** パスと信号形式の両方に明示的な EEG の根拠がある候補は **7.209 TB，45.57％**でした．Archive，汎用形式，他モダリティ，付随ファイルを分離しており，この監査でヘッダーを検証した EEG 量や取得完了量は計測していません．

2026-11-22 に，稼働中の bulk SQLite を読み取り専用の 1 transaction で全件走査しました．対象は **468,040 file jobs，609 pinned releases**，known bytes **15,821,047,310,466 B**，サイズ不明 **38 件**，公開サイズ 0 byte **1,074 件**です．この file job 数はカタログ全体の dataset 数とは異なります．異なる公開版や mirror に同じ記録が含まれるかも未解決です．

## 今後の優先度の根拠

1. **明示 EEG 信号候補の header と companion を先に検証します．** 根拠が最も明確な 135 releases から，使用可能な channel，サンプリング周波数，単位，記録長，必要ファイルの組合せを確定するのが合理的です．公開サイズ 0 byte の候補は使用可能な波形として扱いません．
2. **MEG の同時 EEG と汎用形式を，小さいメタデータから確認します．** EEG を含むマルチモーダル記録を誤って落とさず，ECG だけの EDF 等を誤って EEG に数えないためです．
3. **未認識拡張子の中で大きい部分を確認します．** 固定ルールで未確認に残った `.poly5` は 450,309,521,725 B／2 releases，`.cdt` は 301,969,584,000 B／1 release です．この合計 752,279,105,725 B は，全 known bytes の約 4.75％に当たります．拡張子と容量だけで EEG へ昇格せず，仕様と header を確認する対象にします．今回のルール・集計値は変更していません．
4. **Archive は内部一覧と重複関係を確認してから容量を判断します．** 3.404 TB の中身を EEG と仮定すると，大きく見積もりを誤る可能性があります．新規 download はこの監査では開始していません．
5. **派生物と原記録の対応を解決します．** `derivatives` を含むパスは 32,909 files，1,805,403,117,092 B，47 releases にあり，総 known bytes の 11.41％です．これは上記の分類と重なる補助フラグであり，追加加算しません．原記録と同じ時区間を独立した学習時間として数えないために必要です．

パスの明示根拠がない 70 releases のうち，最大は catalog `000096` の 504,027,157,064 B です．続く `003247` は 60,572,737,474 B，`002194` は 26,851,214,000 B でした．これらを EEG 不在として削除せず，公式 scope と対応 reader の確認候補として挙げています．詳細は `audit_followup.json` に保存しました．

## 来歴と検証

Fixture 8 件はローカルと workstation の両方で PASS しました．実台帳では，file 数・known bytes・unknown size の総和一致，分類の排他性，release review の排他性を確認しました．走査時間は 18.14 秒でした．SQLite は読み取り専用で使用し，既存キューの更新・削除・並べ替え，新規 download，controller 操作，学習承認の変更は行っていません．

成果物は `summary.json`，`release_review.csv`，`frozen_protocol.json`，`audit_followup.json` です．公開 report は集計と release 識別子だけを含み，ダウンロード URL・個別の波形パスを含みません．
