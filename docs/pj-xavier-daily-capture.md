# PJ-Xavier｜日常PC作業の同期収録・自動ラベリング・継続学習

決定日：2026年11月26日（JST）  
状態：採用する製品開発方針・設計仕様。統合実装、実機収録、データ転送、学習開始は未確認／未実施の項目を含む。

## 1．目的と採用方針

PJ-XavierはNeuroCoreのAIを研究開発するプロジェクトである。日常のPC作業からEEG・画面・操作履歴を同時収録し、自動ラベリングと継続学習につなげる。従来のPsychoPy内1,000課題（各300秒を上限とする実験環境）は統制実験と回帰検証のために保持する。日常作業の収録には専用課題の完遂や手動目的入力を必須としない。

画面の時系列・操作履歴・作業結果を教師LLM/VLMに与え、高次目的と作業記憶（作業中に保持・更新するとモデルが推定した情報）を生成する。生成結果を正式な製品開発・学習用教師ラベルとして採用する。本人によるラベル付与・毎回の承認は必須工程にしない。ラベルの根拠・生成条件・不確実性を保存し、根拠不足は不明として扱う。LLM生成ラベルが本人の内的意図・作業記憶の独立した生理学的真値であるとは主張しない。

## 2．システム構成と役割

収録PC → S Mac受信領域 → 品質・同期検査 → S Mac上の教師LLM/VLM → 学習データ整形 → PJ-Xavier学習・評価 → NeuroCore外部デコーダ。

- 収録PC：本人が明示的に開始・一時停止・終了できる収録セッション。許可された画面／アプリの画像、操作イベント、Muse 2等のEEGを共通時刻で記録する。既存Xavier Recorderのセッション管理、BrainFlow/LSL、保存・検査処理を再利用候補とする。
- S Macクラスター：承認された専用の受信・保管領域へ収録PCから直接データを転送する。受信後の整合性検証、品質判定、ラベル生成、前処理、学習、評価を担当する。原データ・個票・モデル重みは許可された保存範囲内に限定する。
- Ubuntu管制塔：マニフェスト、ジョブID、処理状態、匿名集計、資源・失敗監視、排他とスケジューリングを管理する。画面動画、キー入力、脳波の大容量ペイロードを中継・保存する経路にはしない。
- NeuroCore：推論結果を外部デコーダのIntentCommandとして受け取り、安全性検証とaction envelope生成を担う。学習用RecorderはOS全体の自動操作や製品の安全制御を代替しない。

## 3．収録データ契約

初期候補は既存のMac＋Muse 2（TP9、AF7、AF8、TP10の4ch、256Hz）。画面は5〜10fps、操作はイベント発生時、転送単位は約5分を暫定値とする。実測欠損・遅延・容量・画面変化を確認して設定を固定する。EEGの元サンプルは装置時刻、単位、チャンネル情報、受信時刻を保持する。

1セッションに participant_id（仮名）、session_id、segment_id、時計系、収録条件、スキーマ版を割り当てる。

- EEG：XDF/元形式（EDF・BDF等も入力可）。サンプル番号、装置時刻、受信時刻、単位、チャンネル、欠損・品質フラグ。
- 画面：MP4または画像列。各フレームのキャプチャ時刻・PTS・サイズ・欠落・表示可否を別表に記録する。
- 操作：JSONL。許可した作業内の操作種別、時刻、必要な座標や操作対象、状態変化。認証情報や生のキー列・クリップボードの包括収集を既定にしない。テキスト内容は明示承認した非機密の実験入力のみ保存する。
- 同期：events.tsv／clock_map.json。共通イベントID、時計対応、ドリフト、遅延、時刻誤差、取得可能時刻、校正結果。
- manifest.json：ファイル名、バイト数、SHA-256、セッション・区間、出典、同意・利用範囲、収録ソフト版、QC状態。
- labels.jsonl：segment_id、予測対象時刻、作業区間、目的階層、作業記憶の状態と差分、操作の意味、観測された作業結果、根拠フレーム／イベントID、教師モデル・プロンプト版、信頼度、不明・矛盾フラグ。

画面・入力のソフトウェア時刻だけでEEGとの物理的同期を保証しない。Bluetooth遅延、画面の実表示とキャプチャ、取得可能時刻、途中切断を別々に計測する。正式な研究・評価には独立した時計校正が必要である。

## 4．直接転送とデータ管理

収録PC側で完結した区間を検査・封印し、認証済みの暗号化通信により承認されたS Mac受信ノードへ直接送る。通信断の場合は暗号化したローカルスプールへ一時保管し、容量上限では収録を停止して知らせる。受信側は一時領域からmanifestとサイズ・SHA-256を照合して確定する。session_id/segment_idとhashで冪等性を担保し、再送で重複学習しない。転送受領と学習適格化は別の状態とし、確認前にローカル原本を削除しない。

処理状態は captured → sealed → received → validated → labeled → admitted → trained/evaluated を基本とし、quarantined、failed、revokedを別管理する。Ubuntuは大容量の中身ではなく状態と集計を監視する。受信ノード・保存期限・容量上限・鍵管理・アクセス権は実機配備前に確定する。ネットワーク公開、無制限の共有、未承認のクラウド転送は行わない。

## 5．教師LLM/VLMによる正式ラベル生成

作業全体の画像列と許可済み操作履歴から、作業区間を分割する。操作 → 局所目標 → 作業目的 → 高次目的の階層と、作業記憶（参照対象、条件、選択、進捗、未解決事項、次に必要な情報）の時系列を生成する。作業終了後の画面や結果も教師側の推定材料として利用できる。

生成ラベルは構造化スキーマ、参照時刻、実際の操作・状態変化との整合性を機械検査する。根拠のない断定や機密内容の復元を求めない。教師モデルの版・設定・入力根拠と再生成履歴を固定し、未知・矛盾・低確信の区間は保留または不明ラベルにする。採用済みラベルは正式な学習目標であり、手動で高次目的を記入することを収録条件にしない。

## 6．学習・評価

学習対象のEEG対応LLM/VLMには、予測時点以前に実際に利用可能なEEG・画面・過去操作履歴だけを渡す。教師が後から生成した目的・記憶・次操作を出力側の教師信号にする。予測時点以降の画面・操作・結果・要約・フィルタ支持を入力へ漏らさない。教師の事後推定を時点tで本人が既に知っていた事実として自動コピーしない。

参加者・セッション・作業区間の重複を排除し、splitを固定する。同一作業の近接窓や派生ラベルをtrainとtestに跨がせない。固定候補を同じ画面・履歴・計算予算で比較し、EEGあり、strict noEEG、時間ずらし、対応を崩したEEGを評価する。目的ラベル一致だけでなく、次操作の正確さ、独立した最終状態／タスク成功、棄権、誤操作、遅延、言語・画像能力保持も測る。実測EEGでの高次目的・Lv.8能力の主張には、独立した目的・同期・安全性・未知条件の評価を別途要求する。本人確認済みラベルは製品学習の必須条件にせず、科学的検証用の独立評価として区別する。

## 7．実装順序と完了条件

1. 既存Recorder棚卸しと日常作業用セッション収録。明示開始・停止、収録中表示、許可範囲、保護画面除外、模擬EEG・画面・操作の通し保存と再読込を検証する。
2. 実機Muse 2連携と時計校正。短時間、次いで30分の承認された技術試験で、欠損、時刻対応、安定性、保存容量を計測する。人工EEGは研究用実測データから分離する。
3. S Mac受信パイロット。合成データで転送、再送、hash不一致の拒否、アクセス制御、受領確認、容量・停止条件、匿名集計を検証する。
4. 教師LLM/VLMラベル生成。合成・非機密の許可済み収録で区間分割とschema検証、根拠参照、不明処理、版管理を確認する。
5. 学習接続と有限ジョブ。適格データのみを固定manifestから投入し、保存・再読込・保持評価・強対照を確認する。改善がない学習を自動拡大しない。
6. 承認済み実作業でのMVP。収録→直接転送→品質検査→ラベル生成→学習→推論の一連の動作と停止・復旧を確認する。NeuroCoreの実操作は別の安全ゲートを通す。

## 8．プライバシー・運用上の境界

本人が収録範囲を理解し、許可した作業のみ対象にする。非収録状態を既定とし、収録中表示、即時停止、対象アプリ／ウィンドウの許可リスト、権限の明示を必須とする。パスワード・認証画面・個人情報・業務機密・第三者の通信は記録前に除外する。安全な判別ができない場合は画像・操作の収録と転送を止める。秘密情報が混入した区間は隔離し、学習対象にしない。共有ストレージ利用条件、必要な倫理手続、同意・撤回、保持期限、データ削除、アクセス権を実運用前に確認する。

公開GitHubには設計・合成fixture・匿名集計・コードだけを置き、実作業の画面、操作ログ、EEG個票、認証情報、非公開接続先、学習用原データは登録しない。既存のPsychoPy版・学習済みモデル・取得ジョブはこの設計決定のみで変更しない。

## 9．現在の位置付け

既存Recorderには人工EEGを使ったPsychoPy収録・XDF/動画再読込の検証実績がある。1,000課題の実装は再利用可能だが、日常PC作業の収録・実機EEG・物理同期・直接受信・LLMラベル連携・実データの継続学習は今回の仕様をもって完成したことにはしない。製品開発を進めるための教師ラベル採用と、独立した研究評価の成立条件を分ける。
